# 内容结构与功能写法

## 文档前置内容

封面、版本记录、自动目录。版本记录列明版本、日期、修改内容和编制信息；未知的单位或人员由项目资料补充。

## 推荐章节

| 章节 | 应包含的内容 |
|---|---|
| 一、项目综述 | 编制目的、背景、建设目标、用户角色、建设内容、术语；必要时简述现有系统基础 |
| 二、业务流程分析 | 总体流程、角色职责、核心场景、状态变化、异常分支 |
| 三、总体产品设计 | 产品组成、各端职责、信息架构、主要模块关系、业务数据流向 |
| 四、功能需求 | 功能总表；按端或业务模块展开详细需求；前后台对应关系；接口与数据要求 |
| 五、实施与验收 | 阶段范围、交付物、实施配合、测试与验收标准；确定的计划或待明确的安排 |
| 六、部署与运行保障 | 与项目相关的部署、性能、安全、权限、日志、备份恢复要求 |
| 七、培训与服务 | 用户培训、操作文档、上线支持、维护方式和已明确的服务要求 |

按项目实质调整章节：小项目可合并总体设计与流程，详细产品 PRD 可将数据、接口和非功能需求独立成章。保持章节编号连续。正文篇幅由需求复杂度决定。

| 需求编号 | 模块 | 功能 | 需求描述 | 说明 |

## 单项功能描述

按业务复杂度使用以下字段，简单功能可以合并成连贯段落。

| 字段 | 需回答的问题 |
|---|---|
| 需求编号与名称 | 这是什么功能，如何引用 |
| 使用角色与目标 | 谁使用，要完成什么业务 |
| 入口与前置条件 | 从哪里进入，需要满足什么条件 |
| 主流程 | 用户操作、系统处理、最终结果 |
| 业务规则与状态 | 条件、计算、时限、状态流转、重复操作 |
| 数据与展示 | 关键字段、来源、必填项、校验与展示 |
| 后台与权限 | 谁配置、谁审核、谁查询、如何留痕 |
| 异常处理 | 失败、撤回、取消、退款、超时等相关分支 |
| 验收标准 | 在明确条件下进行什么操作，应得到什么可观察结果 |
| 待确认项 | 未确定的参数、决策、接口条件及其影响 |

## 示例：预约审核

**REQ-BOOK-001 预约审核。** 管理员审核员工的设备预约申请；员工在预约详情查看结果。以下为拟建设需求，现有系统审核能力待验证。

员工提交申请后进入“待审核”。管理员查看设备、数量、时段及用途，选择通过或驳回；驳回时填写原因。系统记录审核人、处理时间及结果。

建议规则：待审核申请占用对应时段的可预约数量，驳回或取消后释放；此占用时机待业务确认。审核前再次校验申请状态。审核与取消并发时，仅允许一次有效状态变更，后续操作显示最新状态。

验收示例：在上述占用规则确认后，某时段原有 2 台可预约设备，申请 1 台后余量为 1；驳回后恢复为 2，重复请求不会再次增加余量。普通员工无法审核他人的申请。

## 参数、接口与交付表

- 参数表：参数名称、取值、适用条件、确认状态。
- 接口表：对接系统、业务目的、数据方向、关键数据、触发时机、失败与重试、配合条件。
- 交付表：阶段、需求编号范围、交付物、验收依据、前置条件。
- 待确认表：问题、影响范围、建议方案、需确认方、确认结果。

这些表按项目需要采用。描述现有系统时依据可核实资料；文档中的拟实现流程与已验证能力分别表述。
