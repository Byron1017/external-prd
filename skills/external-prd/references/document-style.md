# Word 排版规范

这是一套以仿宋和黑色文字为核心、经过统一整理的默认规范。用户提供明确的字体、字号或版式要求时，以其要求为准。

## 页面与字体

- A4 纵向；上、下页边距 2.5 cm，左、右 2.0 cm；页眉、页脚距边界 1.2 cm。
- 中文默认仿宋（FangSong），西文和数字默认 Times New Roman。显式设置东亚字体和西文字体，避免主题字体覆盖。
- 字体缺失时优先使用可用的仿宋类字体；再选择宋体类替代，并记录实际字体。字体替换后重新检查分页。字体通过系统安装，不随文档包分发字体文件。
- 黑色 #000000 为正文和标题主色；辅助说明 #666666；细线 #BFBFBF；表头底色 #F2F2F2。

## 章节与目录

命名示例：

```text
一、项目综述
1.1 项目背景
1.1.1 业务现状
二、业务流程分析
2.1 总体业务流程
2.1.1 申请与审核
```

- 正文通常使用三级标题，更细的规则用编号列表或表格。
- 一级标题用中文数字和顿号；二、三级用阿拉伯数字及点号，编号后空一格。
- 一级中文序号与子级阿拉伯序号对应。使用关联 Heading 1/2/3 的多级列表时，子级引用上级编号应启用法律样式编号（OOXML `w:isLgl`），使“一”在子级显示为“1”。二级随一级重新开始，三级随二级重新开始。
- 若制作工具无法可靠支持混合编号，可根据唯一的章节树生成标题文本编号，同时保留真实标题样式与大纲级别。此时不要再叠加自动编号，结构变更后整体重算编号。
- 标题名称短而具体，同级保持一致，例如“会员管理、积分管理、活动管理”。
- 自动目录收录三级标题，页码右对齐，使用点状引导符。目录和封面标题采用不进入正文目录的专用样式。
- 使用 TOC 字段（如 `TOC \o "1-3" \h \z \u`）。插入字段或开启更新标志不等于已生成目录页码；应使用 Word、WPS 或兼容办公引擎更新字段后保存、渲染。
- 封面不显示页码；目录之后分节，正文从第 1 页开始。页码使用 PAGE 字段。

## 表格与图示

- 功能总表优先用“需求编号、模块、功能、需求描述、说明”五列。长规则在正文展开。
- 表格占满正文可用宽度；表头浅灰、加粗；边框 0.5 pt。跨页重复表头，短行尽量保持完整；超长行允许跨页，避免大片空白。
- 宽表优先拆分或减少列数；确需横向页时单独分节。保持可读字号。
- 流程图用简单方框、箭头和少量灰阶，明确角色、步骤、分支、结果。架构图按职责分层。
- 截图裁去无关区域，确保文字可读，并标注“现有系统示意”或“拟设计示意”等真实状态。
- 图表按章编号，例如“图 3-1 预约审核流程”“表 4-1 功能需求总表”，正文引用相同编号。
- 封面以项目名称、文档名称、编制单位、日期、版本为主；正文以文字、表格和必要图示组织内容。
